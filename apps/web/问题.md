
# 遇到的问题
1. 用户导入模式时，模型内容中存在多级层级，真正的模型在最内层，逐层选择很麻烦
去除掉多余的层级，将模型内容放到根目录下。没有使用 threejs 自带的 flatten 方法，因为直接使用这个方法，会使得内部某些部件相对位置不对。
使用自定义的 bakeFlatten 方法，把世界矩阵直接作用到顶点上。顶点是点集,任意仿射矩阵(含切变)作用其上都是精确的,因此相对位置不会丢失。

2. 用户导入自定义的模型，但是单位不同，尺寸会有很大差别
进行启发式自动修正，首先根据模型的最长边来大致判断模型的单位是什么
- 最长边 ≤ 10m(在带内或偏小)→ ×1 不动(偏小更可能是合理小物件,不冒险放大);
- 偏大 → 在 cm/mm 公制因子里选换算后最接近 1m 的 → 缩小到米制
- FBX格式，头部带 UnitScaleFactor（通常 cm），转换时一般已被应用，可以不被转化

3. 旋转场景，活动的范围很大，即使选中某个物体也是这样
封装 Three.js 的 OrbitControls 控制器（OrbitCameraControl.ts），自行实现右键点击时以被指向的模型为中心旋转场景  
自行实现之前，主要的问题是：为了将右键指向的模型作为旋转场景的中心点，用右键点击来选中没有在视图中间的模型时，相机会自动指向这个模型而导致视图跳动。
**原因：**
原生 OrbitControls 强制相机始终"看向" target，而 target 既是旋转中心、又是视线中心——这两个角色被绑死了。并且它每帧都会执行`camera.lookAt(target)`，将相机镜头对准target

**封装的逻辑：**
- 右键交给自定义逻辑（mouseButtons.RIGHT = null），左键平移、中键缩放保持不变
- 右键拖拽时绕轴心旋转：同时旋转相机的位置（position 绕轴心）和朝向（quaternion 叠加同一旋转），使轴心点在屏幕上保持原位 → 不再跳动
- 旋转期间 update() 跳过 orbitControls.update()，避免其 lookAt(target) 把朝向拉回；松开右键后把 target 重新对齐到视线方向，让 OrbitControls 平滑接管
- 俯仰角做了极角夹紧，防止翻转
- 自定义旋转进行时跳过 OrbitControls 更新，避免其 lookAt(target) 覆盖朝向，将“看向哪里”和“绕哪里转”分开

4. 操作指令
- 最初设计是每个指令用来处理一种操作，比如新增模型、修改场景属性、修改模型的基本参数、修改模型的材质值等，粒度太粗
- 然后想细粒度，根据属性路径和修改方式，将对三维模型的修改都放到一个指令里面，且每次修改一个属性的时候，就只修改和记录这个属性的旧值和新值，但是还是有点麻烦
```typeScript
type ApplyMode = 'assign' | 'copy' | 'set'

export class HandleModelCommand implements ActualCommand {
  private oldValue: unknown

  constructor(
    private object: THREE.Object3D,
    private path: string,        // "material.roughness" / "material.color" / "position.x"
    private newValue: unknown,
    private mode: ApplyMode = 'assign',
  ) {
    const { parent, lastKey } = this.resolve()
    // 在构造时快照旧值，copy/set 模式必须 clone
    this.oldValue =
      mode === 'assign' ? parent?.[lastKey] : parent?.[lastKey]?.clone()
  }

  private resolve() {
    const keys = this.path.split('.')
    const lastKey = keys.pop()!
    const parent = keys.reduce<any>((o, k) => o?.[k], this.object)
    return { parent, lastKey }
  }

  private apply(value: unknown) {
    const { parent, lastKey } = this.resolve()
    if (parent == null) {
      console.warn(`[HandleModelCommand] 路径无效: ${this.path}`)
      return
    }
    switch (this.mode) {
      case 'copy': parent[lastKey].copy(value); break
      case 'set':  parent[lastKey].set(value);  break
      default:     parent[lastKey] = value
    }
    // 副作用：材质改动必须重编译 + 打持久化标记
    if (parent instanceof THREE.Material) {
      parent.needsUpdate = true
      this.object.userData.materialModified = true
    }
  }

  execute() { this.apply(this.newValue) }
  undo()    { this.apply(this.oldValue) }
  redo()    { this.apply(this.newValue) }
}

```
- 最后通过回调来做，将对该属性的修改操作通过回调函数传入指令中，指令就单纯做更改操作的中转
  同时，将属性面板的页面更新方式变了，使用 computed 逐个更新，结合状态值来更新，比如 materialVersion 

- 总是会有改完之后，切换对象或场景后，回退错位的情况!!!  --  处理了

- 最难的地方，就是 LLM 返回的内容，如何解析到对应的指令，之前是一股脑将同类的修改都进行保存、赋值，比如要修改position.x，之前的话会一起记录位置、旋转、缩放的值作为一个 newState 
现在是将所有的能修改的属性都放到一个注册表中，查找对应对象中的这个属性的旧值，然后执行修改操作。之后如果有新的同类的属性，就可以直接在这个注册表中新增，如果是有不同类型的属性或操作的话，就还要新增执行函数
